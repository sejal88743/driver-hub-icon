I have an existing production PWA application using Supabase as the backend database.

IMPORTANT:
DO NOT change, delete, rename, migrate, or recreate any existing Supabase tables, columns, relationships, RLS policies, or existing data.

The current application has:
- 20,000+ bills
- Party master data
- Receipt/payment entries
- Bill-wise payment allocation
- Multiple users/devices using the same online Supabase database
- Existing authentication and existing Supabase integration

The application is currently slow because large amounts of data are being fetched repeatedly from Supabase.

Your task is to optimize the existing application for 100,000+ bills without changing the existing Supabase database structure.

==================================================
PRIMARY OBJECTIVE
==================================================

Convert the application into a:

LOCAL-FIRST + SUPABASE-SYNC architecture.

The application must work like this:

PWA UI
  ↓
IndexedDB local database
  ↓
Fast local search and display
  ↓
Sync Manager
  ↓
Existing Supabase database

Supabase remains the central source of truth.

IndexedDB is used only as a local performance cache and offline queue.

==================================================

DO NOT modify the existing Supabase schema.

Do not:
- Create new Supabase tables
- Add new Supabase columns
- Rename columns
- Delete columns
- Change existing data types
- Change relationships
- Change RLS policies
- Rebuild the database
- Migrate existing data

The current Supabase database must continue working exactly as it works now.

First inspect the existing Supabase queries and existing schema usage in the code.

The IndexedDB structure must adapt to the existing Supabase schema.

- IndexedDB

==================================================

When a new receipt/payment is entered:

2. Save the payment immediately to IndexedDB.
3. Update the UI immediately.
4. Add the operation to the local sync queue.
5. Try to sync with Supabase immediately.
6. If internet is unavailable, keep the record pending.
7. Retry automatically when the internet returns.

Payment flow:

New Payment
   ↓
IndexedDB
   ↓
UI updates immediately
   ↓
Supabase sync
   ↓
Success → mark synced

If internet is unavailable:

New Payment
   ↓
IndexedDB
   ↓

   ↓
Internet returns
   ↓
Automatic retry
   ↓
Supabase

IMPORTANT:
Never lose a payment entry because of a temporary internet failure.
